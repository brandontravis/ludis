### 3. Add Hybrid Platform Scanner (NEXT)

**Problem:** Platforms with BOTH root-level ROM files AND subfolders cannot be properly configured.

**Example:** Nintendo Wii has:
- 32 .iso files at root level
- 1,233 .rvz files in RVZ/ subfolder

**Current limitation:**
- `type: files` = scans root files only (misses RVZ/)
- `type: folders` = scans subfolders as games (wrong)
- `type: nested` = only handles subfolders (ignores root files)
- No option to scan BOTH root files + subfolders

**Impact:** 
- Wii: 97.5% lb_only (1,233 games missing from inventory)
- PS3: 48.8% lb_only (likely similar subfolder issue)
- Saturn: 49.7% lb_only
- MS-DOS: 48.6% lb_only

**Requirements:**

1. **NO PERFORMANCE DEGRADATION**
   - Scanner must remain fast (< 10% increase in scan time)
   - MUST NOT iterate through all files during discovery
   - Peek at first 5-10 items only (like current code)
   - Full scans only during actual inventory building

2. **Add "Both" Option** to discovery flow when mixed content detected:
   ```
   [?] This folder contains 32 ROM files AND 1 subfolder.
   What should I scan?
     > Files only (ignore subfolders)
     > Subfolders only (ignore root files)
     > Both (files + check subfolders)  ← NEW
     > Skip
   ```

3. **Resulting Config** for hybrid case:
   ```yaml
   Nintendo Wii [2006]:
     type: nested
     scan_paths:
       - path: ""       # Root level files
         type: files
       - path: "RVZ"    # Subfolder files
         type: files
   ```

4. **Show Samples** at every decision point (first 5 items)

**Implementation Notes:**
- Only peek at filesystem structure (not full scan)
- Ask user about each subfolder when "Both" selected
- Use existing `configure_nested_path()` logic where possible
- Keep simple cases fast (auto-detect when all files or all folders)

**Files:** `scripts/interactive_scanner.py`

## What This Actually Is

**The product:** Migration script generator

**The flow:**
1. LaunchBox XML → CSV (intermediate data)
2. Filesystem scan → inventory (intermediate data)
3. Reconcile + filter → master inventory (intermediate data)
4. User selects platforms + filters → **migration package** (THE PRODUCT)

The CSVs are just steps to get to the migration scripts.
